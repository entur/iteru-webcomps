Dropping VehicleForm into your app

A practical walkthrough for the app embedding these components: installing the package, wiring the session provider and auth, and handling new / edit + save / cancel. Everything here is about what you pass in and the callbacks you receive — nothing about how the component works inside.

The library gives you data-aware form components — VehicleForm and VehicleTypeForm. You wrap them in a SobekProvider carrying the GraphQL endpoint, a way to authenticate, and the organisation the data belongs to; each form then takes (optionally) the id of a record to edit. It loads the record, renders the form, and saves changes back for you. You don't write queries, mutations, or a save handler.

1Installing the package

Install from a GitHub Release. The repo is public, so the tarball URL needs no token:
npm i https://github.com/entur/mui-comps-nmr/releases/download/v0.9.0/entur-mui-comps-nmr-0.9.0.tgz

Releases are listed at github.com/entur/mui-comps-nmr/releases. Each carries one .tgz asset plus a note recording which sobek schema it was built against. The package is not on the npm registry — npm i @entur/mui-comps-nmr returns a 404.

Upgrading means editing the URL. A URL install pins that exact URL in your package-lock.json, so ^0.9.0 ranges don't work and npm outdated will never tell you a new version exists. Watch the Releases page and bump the URL by hand. This is the cost of not being on a registry — the version scheme is already registry-ready, so if that changes, the install command is the only thing that changes.

Peer dependencies

All of these are externalized from the build — the host must have them installed, and their major versions are pinned to match hathor. Externalized means the host supplies one shared copy; if these ever resolve to two copies you get invalid-hook-call errors and MUI styles not applying.

PackageRangeNote
react, react-dom^19.1.0React 19 only.
@mui/material^7.0.2Every control is MUI v7.
@mui/icons-material^7.0.2
@mui/x-data-grid^8.29.1Loaded lazily, only when a grid field renders — but still required.
@emotion/react, @emotion/styled^11.14.0MUI's styling engine.
graphql-request^7.4.0The GraphQL transport used by the data-aware wrappers. Pulls in graphql (its own peer, 14 - 16) — npm and yarn install it for you; under pnpm add it yourself.
The library never touches your GraphQL client. graphql-request is a thin fetch wrapper the forms construct per request — it is not Apollo/urql, has no cache, and shares no state with whatever client your app already uses. It is a peer dependency so the host owns the version, and so graphql is resolved once instead of a copy being compiled into dist/.

2Import & the shape of a form

Both components are named exports. They render the fields; the Save/Cancel footer and section TOC are yours to place from a session (§5). You place the component wherever you want the form to appear, anywhere below a SobekProvider.

// VehiclePane.tsx
import { SobekProvider, VehicleForm } from '@entur/mui-comps-nmr';
import type { SobekCtx } from '@entur/mui-comps-nmr';

const session: SobekCtx = { endpoint, getHeaders: authHeaders, dataOwnerRef };

export const VehiclePane = () => (
  <SobekProvider value={session}>
    <VehicleForm netexId="VEH:Vehicle:123" />
  </SobekProvider>
);
Wrapping a form in your own component? The props types are exported too, so you can extend them instead of reconstructing them with ComponentProps<typeof VehicleForm>: 
import type { VehicleFormProps } from '@entur/mui-comps-nmr';

type PaneProps = VehicleFormProps & { title?: string };
Session inputs are not props. endpoint, headers, getHeaders and dataOwnerRef live on the provider (§3), not on the form. Passing them to <VehicleForm> is a type error, and rendering a form with no provider above it throws.

Props you'll use

PropTypeWhat it's for
netexIdstringThe record to load and edit. Omit it at mount to start a blank “new” form (§5).
mode'view' \| 'edit'Default 'edit'. 'view' disables every input and leaves session.footer disabled.
onSaved(netexId) => voidCalled after a save succeeds; receives the saved record's id.
onError(msgs: string[]) => voidCalled with general (non-field) error messages when a save fails, and with the server's messages when a load fails.
onChange(value: Vehicle) => voidThe record as it currently stands in the form. Fires on the load and the post-save refetch too, not only on edits (§6).
sessionFormSessionFrom useFormSession(). The form publishes its Save/Cancel state and its section list into it; you place <EditFooter {...session.footer} /> and <SectionToc {...session.toc} /> (§5).
skeletonPropsFormSkeletonHostPropsariaLabel and sx for the loading skeleton. Its shape is derived and not overridable — see the callout below.
layout, variant, slotProps—Presentation only — which fields/sections show, tabs vs stacked, MUI overrides. Covered in the README.
Field-level errors are handled for you. When a save fails validation, the offending inputs show their messages inline automatically. onError only receives the general messages that don't belong to a single field, so you can show a banner or toast. If a save fails with no usable GraphQL error payload (network drop, malformed response), you still get one message: ['Failed to save'].
The three load outcomes are distinct, and the component renders each itself. While the load is in flight you get a shaped skeleton: one placeholder per field, sized by that field's control kind, laid out in the same sections and tabs the real form is about to draw — so the layout does not jump when the record lands, and the form fades in rather than snapping. The shape is derived from the entity registry and your layout/variant, so it stays correct with no row counts to maintain. Pass skeletonProps={{ ariaLabel: '…' }} to localize what a screen reader announces (the default is English, as everywhere here). A load that settles with no matching record renders Not found: <netexId> — never a blank editable form, since saving one of those would create a new record instead of editing the one you asked for. A load that fails (network drop, auth rejection, server error) renders the load error instead, so a transport failure is never reported to your user as a missing record.
A failed load reaches onError too. Both halves fail alike: the load hands you the server's own messages, falling back to ['Failed to load'] when the payload carries no GraphQL errors. It fires once per record, and never for a load the form has already moved on from — so a retry button, a redirect or a log line can hang off the callback rather than off your own detection. The same messages are rendered in place of the form, joined into one line.

3Session & auth — the SobekProvider

One provider, mounted once near the top of your app, supplies every form below it with the endpoint, the credentials, and the organisation whose data you're working on. It is mandatory: a data-aware form with no provider above it throws with mui-comps-nmr: this component must be rendered inside a <SobekProvider>.

// Session.tsx
import type { ReactNode } from 'react';
import { SobekProvider } from '@entur/mui-comps-nmr';
import type { SobekCtx } from '@entur/mui-comps-nmr';

const session: SobekCtx = {
  endpoint: 'https://sobek.example/graphql',
  headers: { 'X-Tenant': 'entur' },
  getHeaders: async (): Promise<Record<string, string>> => ({
    Authorization: `Bearer ${await auth.getAccessToken()}`,
  }),
  dataOwnerRef: 'NOG:Authority:cP4aPiJ7c39',
};

export const Session = ({ children }: { children: ReactNode }) => (
  <SobekProvider value={session}>
    {children /* …anything, at any depth… */}
  </SobekProvider>
);
FieldTypeWhat it's for
endpoint requiredstringThe GraphQL URL to load from and save to.
dataOwnerRef requiredstringThe organisation owning the data, e.g. NOG:Authority:cP4aPiJ7c39. Filters every load and stamps every save (see below).
headersRecord<string,string>Static request headers (fixed API keys, client names…). Sent as-is on every request.
getHeaders() => headers \| Promise<headers>Headers computed at request time — the right home for an Authorization token. May be async, so it fits token providers that refresh in the background.
You can use both header fields. When headers and getHeaders are both set they're combined — getHeaders wins on any key it also sets. So put constants in headers and the token in getHeaders. Because getHeaders is called immediately before each request, a token that refreshes in the background is always picked up, with no re-render needed.

dataOwnerRef — the organisation

This is the tenant discriminator, and it is handled differently from the headers on purpose:

  • It filters the load and the post-save refetch, so a form only ever shows records belonging to that organisation.
  • It is stamped onto every save from the provider, never taken from what's on screen — a record loaded under one organisation can't be written back under another.
  • It renders as a locked field: visible in the form, always disabled, even in edit mode. Your user sees which organisation they're working in and cannot change it.
  • Unlike the headers, changing it reloads every mounted form (§4).
Switching organisation is a real state change. Point the provider at a new dataOwnerRef and every mounted form re-loads against it. If a user has unsaved edits when that happens, they are replaced by freshly-loaded values — prompt before switching if that matters in your app.

4Reloads — what triggers one

A reload replaces whatever the user was editing with freshly-loaded server values, so it matters what can cause one. The list is short:

What changesEffect
netexId propReloads that record (or, if it becomes undefined, retires the in-flight load — see §5).
endpoint on the providerNew client, reloads.
dataOwnerRef on the providerReloads every mounted form — an organisation switch means different data.
headers / getHeaders on the providerNothing. They're read fresh on every request, not watched.
Inline headers/getHeaders literals are safe. They're read per request rather than treated as dependencies, so a new object or closure on every render costs nothing — no re-authentication, no reload, no lost edits. You do not need useCallback, useMemo, or module-scope constants for them, and an inline value={{ … }} on the provider is fine too: it memoizes per field.
The flip side: changing credentials alone won't reload the record. Since the header fields aren't watched, swapping tokens mid-session leaves the currently-loaded record on screen; only the next request uses the new headers. If a credential change should mean “different data,” either change dataOwnerRef with it or force a reload with a key bump (§5).

5New, Save, and Cancel

These three host actions map onto the interface as follows. Note that Save and Cancel come from the session — you place the footer but don't trigger either; you react to the result.

🆕 New

mount without netexId

Mount the form without a netexId and you get a blank create form. On save, onSaved hands you the id of the newly created record.

💾 Save

session footer + onSaved

In edit mode the footer you place from the session performs the save. You listen with onSaved(id) for success and onError(msgs) for general failures.

↩︎ Cancel / discard

session footer

The same footer carries Cancel, which restores the record as the server last returned it — in place, with no reload. Both buttons stay inert until something has actually been edited.

New

// blank form → create a Vehicle (inside your SobekProvider)
<VehicleForm mode="edit" />;

// tell the host when it's been created
<VehicleForm onSaved={(newId: string) => navigate(`/vehicles/${newId}`)} />;
The organisation is filled in for you. A create form shows dataOwnerRef already set from the provider, locked — the user neither picks it nor can change it, and the same value is what gets saved.
Clearing netexId on a mounted form does not blank it. Going from an id to undefined only abandons the in-flight load — the values already on screen stay, deliberately, so an edit in progress is never wiped. To actually get an empty create form from a form that was showing a record, remount it: key={netexId ?? 'new'}.

Save

You don't write save — you place the footer. Create a session, hand it to the form, and render the footer wherever your layout wants it. The footer stays idle (both buttons disabled, actions inert) until a record is loaded in edit mode:

import { EditFooter, useFormSession, VehicleForm } from '@entur/mui-comps-nmr';

const session = useFormSession();

<VehicleForm
  netexId={id}
  session={session}
  onSaved={(savedId: string) => {
    toast.success(`Saved ${savedId}`);
    refetchVehicleList();     // the record is now stale in your list
  }}
  onError={(msgs: string[]) => toast.error(msgs.join('\n'))}
/>
<EditFooter {...session.footer} />   // a page band, a drawer footer, an app bar…
After onSaved, re-pull any of your own copies of the record. The form shows the freshly-saved values itself, but a list or header elsewhere in your app won't know it changed until you refetch it.

Cancel / discard

Nothing more to build: the footer's Cancel restores the record as the server last returned it — the load, or the refetch after your last save. It happens in place, so the form does not remount, does not re-fetch, and the user keeps their scroll position.

// Cancel is in session.footer already. This is the whole integration:
<VehicleForm netexId={id} session={session} onSaved={() => toast.success('Saved')} />
<EditFooter {...session.footer} />
Both buttons stay inert until the form is dirty, and lock again while a save is in flight — so Save can't re-send an unchanged record, and Cancel can't discard nothing. The status line beside them says which state you're in.
The footer speaks English by default. There is no i18n runtime in this package, so pass your own strings — and any styling — as props on your EditFooter: 
<EditFooter
  {...session.footer}
  labels={{
    save: t('common.save'),      cancel: t('common.cancel'),
    dirty: t('form.unsaved'),    clean:  t('form.saved'),
    saving: t('form.saving'),
  }}
  slotProps={{ save: { color: 'secondary' } }}  // per-button MUI props
  sx={{ px: 3 }}                                // applied after every default
/>
Spread session.footer last if you build the props elsewhere — the dirty/saving state is the form's.
Do you still need a key? Yes — for switching records, not for discarding. Setting key={netexId ?? 'new'} guarantees that moving from one record to another — or from a record to a blank “new” form — starts clean, with no chance of one record's edits bleeding into the next. What changed is that you no longer need a rev counter bumped on Cancel: that pattern cost a full reload of data the form already had.
Want Cancel to also leave edit mode? The footer discards; it doesn't change mode. If your page has a view↔edit toggle, drive it from your own button and gate it on session.footer.dirty (§6) so you never leave with unsaved work — see the complete page in §8.

6Watching the form from outside

The form owns the record it is editing, but onChange hands you the current value, and the session's footer.dirty tells you whether anything has been edited.

These are read-only. The form stays the owner of its state — there is no controlled mode, and passing the value back down as a prop is not supported. Watch it; don't drive it.

A header that tracks typing

onChange fires whenever the value moves — on the initial load, on every edit, and again after a save refetches. Because it fires on the load, a title fed from it is correct before the user touches anything:

import { useState } from 'react';
import { VehicleForm } from '@entur/mui-comps-nmr';
import type { Vehicle } from '@entur/mui-comps-nmr';

export function TitledVehicle({ id }: { id: string }) {
  const [live, setLive] = useState<Vehicle | undefined>();

  return (
    <>
      <h2>{live?.name?.value ?? '[ unnamed ]'}</h2>
      <VehicleForm netexId={id} onChange={setLive} />
    </>
  );
}
onChange is not “the user edited something.” It also fires for the load and the post-save refetch, so treating it as an edit signal marks a freshly-loaded form as touched. Use session.footer.dirty for that.

Guarding unsaved changes

session.footer.dirty reports the form's value against the record the server last returned — the load, or the refetch after a save. A saved form is clean again with nothing to reset on your side:

import { useEffect } from 'react';

const session = useFormSession();
const { dirty } = session.footer;

useEffect(() => {
  if (!dirty) return;
  const warn = (e: BeforeUnloadEvent) => { e.preventDefault(); e.returnValue = ''; };
  window.addEventListener('beforeunload', warn);
  return () => window.removeEventListener('beforeunload', warn);
}, [dirty]);

<VehicleForm netexId={id} session={session} />;
Empty is empty, however the control spells it. A switch the user never touched reports false where the record held nothing at all, and a text field typed into and cleared reports ''. Neither counts as an edit. 0 does count — clearing a number that was 0 is a real change.

7Read-only (view) mode

Pass mode="view" to show the same fields with every input disabled (session.footer stays disabled; most hosts don't render the footer at all in view mode) — useful for a details pane or a permission-gated screen.

<VehicleForm netexId={id} mode="view" />

Flip mode between 'view' and 'edit' to drive an Edit button in your own toolbar.

8A complete host page

List on the left, form on the right. Session from the provider, auth from your app's hook, key for clean switching, a live title, and a view↔edit toggle that refuses to leave with unsaved work. The page places Save and Cancel from the session.

import { useState } from 'react';
import { EditFooter, SobekProvider, useFormSession, VehicleForm } from '@entur/mui-comps-nmr';
import type { Vehicle } from '@entur/mui-comps-nmr';
import { useAuth } from './auth';

const ENDPOINT = 'https://sobek.example/graphql';

interface VehiclesPageProps {
  vehicles: Pick<Vehicle, 'netexId' | 'name'>[];
  refetchList: () => void;
  dataOwnerRef: string;
}

export function VehiclesPage({ vehicles, refetchList, dataOwnerRef }: VehiclesPageProps) {
  const auth = useAuth();
  const [selected, setSelected] = useState<string | undefined>();
  const [mode, setMode] = useState<'view' | 'edit'>('view');
  const [live, setLive] = useState<Vehicle | undefined>();   // current form value
  const session = useFormSession();          // footer + dirty

  // no memoization needed — read per request, never a reload trigger
  const getHeaders = async (): Promise<Record<string, string>> => ({
    Authorization: `Bearer ${await auth.getAccessToken()}`,
  });

  return (
    <SobekProvider value={{ endpoint: ENDPOINT, getHeaders, dataOwnerRef }}>
    <div style={{ display: 'flex', gap: 24 }}>
      <nav>
        <button onClick={() => { setSelected(undefined); setMode('edit'); }}>
          + New vehicle
        </button>
        {vehicles.map((v) => (
          <button key={v.netexId} onClick={() => { setSelected(v.netexId); setMode('view'); }}>
            {v.name?.value ?? v.netexId}
          </button>
        ))}
      </nav>

      <section>
        <header>
          <h2>{live?.name?.value ?? '[ unnamed ]'}</h2>
          {mode === 'view'
            ? <button onClick={() => setMode('edit')}>Edit</button>
            : /* Save + Cancel are in the band below. This only leaves
                 edit mode — and refuses to while there's unsaved work. */
              <button disabled={session.footer.dirty} onClick={() => setMode('view')}>
                Done
              </button>}
        </header>

        <VehicleForm
          key={selected ?? 'new'}               // clean switch between records
          netexId={selected}                    // undefined ⇒ new
          mode={mode}
          onChange={setLive}                    // title follows typing
          session={session}                     // footer state + "Done" gate
          onSaved={(savedId: string) => {
            setSelected(savedId);
            setMode('view');
            refetchList();                      // keep the list fresh
          }}
          onError={(msgs: string[]) => alert(msgs.join('\n'))}
        />
        {mode === 'edit' && <EditFooter {...session.footer} />}
      </section>
    </div>
    </SobekProvider>
  );
}
Mount the provider once, high up. It is shown inside the page here to keep the example self-contained, but in a real app it belongs above your router — one provider for the whole session, so every form anywhere in the tree is covered and an organisation switch propagates in one place.

9Checklist

  • install npm i https://github.com/entur/mui-comps-nmr/releases/download/v0.9.0/entur-mui-comps-nmr-0.9.0.tgz — no token. Upgrades are manual URL edits. Host supplies React 19 / MUI 7 / x-data-grid 8 / Emotion 11 / graphql-request 7.
  • provider SobekProvider is mandatory and carries the whole session — endpoint, dataOwnerRef, headers, getHeaders. None of them are form props any more; a form with no provider above it throws.
  • auth Token → getHeaders (may be async); constants → headers. Both allowed.
  • org dataOwnerRef filters loads, is stamped onto every save from the provider, and renders as a locked field the user can't edit.
  • stable No memoization needed — inline headers/getHeaders and an inline provider value are all safe. Reloads come from netexId, endpoint, and dataOwnerRef only.
  • new Mount without netexId for a blank create form — dataOwnerRef is pre-filled and locked; get the new id from onSaved. Clearing netexId on a live form keeps its values — remount to blank it.
  • save Built in — place <EditFooter {...session.footer} /> from useFormSession() wherever you like; you react via onSaved / onError.
  • cancel Built in too — the session's Cancel restores the server's last copy in place, no remount and no re-fetch. Both buttons are inert until the form is dirty, and locked while saving.
  • labels Footer strings are English by default; pass your own (and any sx/slotProps) as props on your EditFooter.
  • watch onChange gives you the current record (load and post-save refetch included, so it is not an “edited” signal); session.footer.dirty gives you edited-vs-clean. Both are read-only — the form keeps owning its state.
  • key Set key={netexId ?? 'new'} so switching records always starts clean. You no longer need a rev counter for discard — Cancel handles that without a reload.
  • refresh After onSaved, refetch any list/header copies of the record you keep.
  • view mode="view" disables inputs and the session's footer.
  • load Three distinct outcomes, all rendered for you: a shaped skeleton while in flight, Not found: <netexId> for a settled empty load, and the load error for a failed one. onError fires for a failed load as well as a failed save.
